## 1. Mission & Project Identity
You are an autonomous AI game engineering agent building **Namma Auto: Chennai Rickshaw Simulator 3D**, a culturally authentic, 60 FPS Android driving and auto-rickshaw economic simulator set in Chennai, Tamil Nadu, India.

* **Target Platform:** **Android only** (Google Play). Do not add iOS, desktop or web export presets, plugins or code paths.
* **Target Engine:** Godot Engine **4.5.1** (pinned in CI; Sentry SDK needs 4.5+), `mobile` renderer with OpenGL ES 3 fallback, **Jolt Physics 3D**.
* **Primary Language:** Statically-typed **GDScript 2.0** (strict typing enforced on all variables, parameters, and return types).
* **Target Hardware Baseline:** Budget Indian Android smartphones (MediaTek Helio G85 / Snapdragon 680, 3 GB–4 GB RAM, OpenGL ES 3.0 / Vulkan 1.1, 60 FPS target, <85 MB initial download).

## 3. Non-Negotiable Architectural Rules for AI Agents

### Rule 1: Strict Decoupling via `SignalBus.gd`
* **FORBIDDEN:** brittle cross-subsystem paths such as `get_node("../../UI/TouchHUD/Speedometer")`.
* **REQUIRED:** emit and connect typed signals through `SignalBus` (e.g. `SignalBus.speed_updated.emit(kmh)`, `SignalBus.horn_blasted.emit(pos, fwd, radius, tier)`).
* **Input:** touch controls press InputMap actions (`Input.action_press`). Gameplay code reads actions only, so keyboard, touch and tests drive the game identically.

### Rule 2: 100% Static Typing in GDScript
* Every variable, array, dictionary, argument and return value has an explicit type. `untyped_declaration` is set to **Error** in `project.godot`.

### Rule 3: Plain-Text Scene & Resource Hygiene (`.tscn` / `.tres`)
* Never invent `uid://` values when hand-writing `.tscn`/`.tres`; omit `uid=` and let Godot assign. Commit the generated `*.uid` and `*.import` files.
* All tunable gameplay numbers live in `.tres` resources, never in physics code.

### Rule 4: Delta-Trike (3-Wheel) Physics Fidelity
* Never use a 4-wheel template. **1 front centre steerable wheel** (`max_steer_angle_deg = 45.0`) and **2 rear drive wheels**, rear-biased `center_of_mass_offset = Vector3(0.0, -0.25, 0.35)`.
* 3-point `RayCast3D` suspension with anti-roll stabilisation; `12°–18°` roll on two wheels = **"Two-Wheel Side-Tilt Gethu"**.

### Rule 5: Mobile Performance Guardrails
* ≤ **150 draw calls** per frame; shared materials, ETC2/ASTC, `MultiMeshInstance3D` for static props.
* ≤ **18 pooled AI vehicles** within **120 m** of the player. Never `instantiate()`/`queue_free()` during driving frames.
* Physics at a fixed **60 Hz**. Primitive colliders (`BoxShape3D`, `CapsuleShape3D`) on moving bodies.

### Rule 6: Crash Reporting (Sentry) — `docs/CRASH_REPORTING.md`
* `autoloads/CrashReporter.gd` is the **only** code that touches the Sentry SDK. Never write `SentrySDK`/`SentryBreadcrumb` anywhere: the addon (`addons/sentry`, git-ignored, installed by `tools/sentry/install_sentry_addon.sh`) is absent in tests and fresh checkouts, and a bare class name is a parse error there. CrashReporter reaches it through `Engine.get_singleton("SentrySDK")` + `call()`.
* New context comes from `SignalBus` listeners in CrashReporter (breadcrumb category = subsystem: `vehicle`, `savari`, `world`, `ui`, `ads`, `tutorial`, `weather`, `navigation`). Throttle anything that can fire every frame; Sentry keeps only 100 breadcrumbs.
* Handled-but-wrong states (corrupt save, missing resource, impossible value) call `CrashReporter.capture_message(...)` and carry on; don't `push_error` and hope.
* No personal data: `send_default_pii=false`, no names, save contents or raw device ids in tags/context.
* The committed DSN is **empty**. CI stamps the `GLITCHTIP_DSN` secret (passed to the export as `SENTRY_DSN`), release `namma-auto@<version>+<run>` and environment at export (`tools/sentry/stamp_sentry_settings.py`). Never commit a DSN; the crash-reporter suite fails if you do.
* Every Android preset needs `gradle_build/use_gradle_build=true` and `permissions/internet=true` (Sentry Android plugin).
* **Fixing a crash** = `.claude/commands/fix-crash.md`: read the GlitchTip issue (stack, breadcrumbs, tags, player context, release) → a failing headless check that replays it → root-cause fix → full §4 protocol → PR naming the issue id. Resolve the issue in GlitchTip only after the fix ships. One issue per PR.
* Crash backend is **GlitchTip** (MIT, Sentry-compatible): the Sentry SDK addon sends to it, and the `glitchtip` MCP server reads it. Only the DSN changes if we move hosts.

### Lessons recorded (do not regress)
* Pooled `AnimatableBody3D` traffic must be teleported with its collision shape **disabled** and re-enabled the next tick. Teleporting with collision on made Jolt launch the player auto at ~260 m/s.
* Apply longitudinal (drive/brake) wheel forces at **CoM height**; at contact height the trike wheelies.
* Directional shadows use **orthogonal (1 split)**, ≤ 45 m; flat ground meshes don't cast. PSSM-4 cost ~66 draw calls on the greybox alone.
* World flat layers: ground plane at y = -0.15, areas -0.08…-0.02, sidewalks/roads +0.045…+0.08, camera near = 0.1. Closer spacing z-fights from the air.
* Vertex-coloured materials need `vertex_color_is_srgb = true`; sky ambient + bright fog clipped the city to white in the compatibility renderer, so use colour ambient.
* Godot only exports non-resource files listed in `include_filter` — `data/world/*` must stay in `export_presets.cfg` or the APK ships without a map.
* Traffic on the graph uses `Basis.looking_at(travel_dir)`; keep `Array.filter()` results out of typed arrays (it returns untyped `Array`).
* HUD: add all panels before all labels (separate `Panels`/`Texts` layers) and skip outlines on text that sits on a panel. Interleaving them cost ~20 extra 2D draw calls.
* The road graph must be **strongly** connected for GPS: `build_world.py` opens map-edge one-ways both ways; don't remove that step.
* Late listeners read `SignalBus.current_road_graph`; `road_graph_ready` fires deferred once.
* Test runs never touch the player's save: GameState disables persistence when the scene arg starts with `res://tests/`. Use `GameState.reset_profile()` between test cases.
* Effective vehicle stats always come from `GameState.active_stats()` (a fresh duplicate); never mutate the `.tres` at runtime.
* No emoji in UI strings — the default font has no emoji glyphs; Tamil comes from the bundled Noto Sans Tamil fallback.
* UI text and rider dialogue go through `tr("KEY")` with keys in `translations/ui.csv`.
* Wheel rays start **below** the chassis origin so the CoM offset sits ~0.55 m above the road; otherwise the auto can never lean.
* The map is **real size (1 : 1)**, ~7 × 6 km around the origin. Jolt clips `WorldBoundaryShape3D` to `physics/jolt_physics_3d/limits/world_boundary_shape_size` (default 2 km): keep it at 20 km in `project.godot` or the auto falls through the ground away from the origin.
* Road surfaces are pre-triangulated in Python (`tools/osm/streets.py`, mapbox-earcut) from osm2streets; the game only copies arrays into one `ArrayMesh` per chunk. Don't triangulate road polygons at runtime. Lane arrows (540k polygons) are deliberately skipped — use decals.
* The road graph takes lane counts/widths from osm2streets (`streets.way_lanes()`), so traffic sits in the drawn lanes. If you change one, rebuild both (`build_world.py`).
* Building walls collide through **one** `ConcavePolygonShape3D` per chunk (static only). Don't go back to a box per building.
* Kick-start rhythm and other timing use accumulated physics time, never `Time.get_ticks_msec()`, so tests under `--fixed-fps` stay deterministic.
* Packed arrays read out of a `Dictionary` are **copies**: `(d["v"] as PackedVector3Array).append(x)` silently does nothing. Keep growable buffers as class members (see `WorldChunkStreamer.MeshBuf`).
* `Vector2` is 32-bit: a time window stored in one can round past a `float` "now" (forced rain once stayed off). Pad the start.
* In tests, `await get_tree().physics_frame` resumes **before** nodes' `_physics_process` that frame: wait 2 frames after `Input.action_press` before asserting `is_action_just_pressed` effects.
* Real audio files override the synth automatically when present (`VehicleAudio.stream_or()`); keep the synth fallback so tests and builds never depend on downloads.
* Never gate core play (free roam, Savari, the King Deluxe) behind Driver Level — only cosmetics and the EV.
* Building detail (sunshades, parapets, head-room + Sintex tank, AC units, awnings) and street dressing (poles, wires, transformers) go into the chunk's **one** building mesh using the plain atlas cell (`PLAIN_CELL`) + vertex paint. Don't add per-prop nodes or MultiMeshes per chunk.
* Trees are the owner's Tripo models (neem, coconut palm, Ashoka A spreading / B slim, pungai; dress tree codes 0–4 = `bake_trees.py` `SPECIES`), drawn by `StreetTrees` through a FIXED set of world MultiMeshes refilled around the camera: the full model per species near the camera (`tree_near.gdshader`, casts shadows, refilled every 5 m from nearby chunks only) and one impostor MultiMesh for every species further out (ONE upright card per tree that turns to face the camera and blends the two nearest of the `VIEWS` baked views, mirrored for the far half; `tree_impostors.png`, `tree_impostor.gdshader`, no shadows, refilled every 20 m) — 6 draw calls for 33k trees. Nov 4 device test ("tree glitch still there"): the old 4 crossed cards had straight-up normals, so every far tree was a pale flat blob that turned into the dark self-shadowed model at 56 m, showed thin bright slabs edge-on and cost 4× alpha overdraw; with `cull_disabled` a billboard's back face flips NORMAL, so the card shader re-sets NORMAL in fragment(). `card_tone` (0.75) / `sky_lean` were calibrated by rendering each model next to its card in the same frame (matched to ~5 % in linear green) — re-calibrate after re-baking the atlas. Between 52 and 60 m (`NEAR_M` ± `FADE_M`) a tree is in BOTH sets and the shaders dither complementary pixels from the same `eye_pos` (set by StreetTrees, never `CAMERA_POSITION_WORLD`, which is the light in the shadow pass), so it cross-fades: the hard 60 m swap, an un-mipmapped atlas and black transparent atlas pixels read as a flickering glitch on the device (Nov 3). The atlas must import with mipmaps + VRAM compression, every transparent pixel carries the nearest leaf colour (`bake_trees.py` `bleed`), and the card shader raises alpha with the mip level. Per-tree numbers are precomputed in `add_chunk`; rebuilds write into preallocated buffers (no array per tree). Never simplify these models: each leaf card is its own UV island, so meshoptimizer stalls (locked borders) or shreds the cards (free borders); a "fewer, bigger leaf cards" mid LOD looked shredded too (Nov 2). Chunks hand their trees over as `"trees"` meta (`StreetTrees.records`), y from `surface_height` on attach. Retired procedural codes 5–7 draw as neem. Trees have no collision (as before).
* People: characters face **+Z**; walkers set `speed_scale = pace / people.json walk_speed` so feet stay planted. Pedestrian nodes move in `_process`, so they have physics interpolation off.
* Read a SkeletonModifier3D's result in `Skeleton3D.skeleton_updated`; outside it you get the pre-modifier pose.
* Licences: CC0 / CC BY / Pixabay only. Sketchfab "Standard", any NC model, and likenesses of real people (e.g. TV characters) stay out even if downloaded.
* Traffic and the player move along **-Z**; glTF files face **+Z**. Every model needs its facing flag (`TrafficVehicleAI.MODEL_FLIP` / `COW_FLIP`, `TrafficModelFit.attach(..., flip)`) checked with a side render, or traffic drives tail-first.
* Touch controls handle `InputEventScreenTouch/Drag` per finger in `TouchHUD._input` (press on touch-down, padded hit areas, slide between held controls). Don't go back to `TouchScreenButton` actions; they felt late and missed thumbs between buttons.
* Buildings are dropped if **any** 2 m raster cell under the footprint is carriageway (`Raster.count_in_polygon`); checking corners only let large footprints stand on roads.
* A Control placed straight under a `CanvasLayer` may get size 0 from anchors here; size it from the viewport (see `ChennaiBackdrop._fit`).
* Don't measure "stuck" on a frozen auto with a stale speed; settle it first (phase 5 was flaky).
* Painted UI art lives in ONE atlas (`assets/ui/controls_v2.png`, `TouchHUD.ART_CELLS`); keep new button art in it so the HUD stays one 2D batch. The Stitch PNGs are flat RGB with painted checkerboards: `import_game_art.py` cuts them out, never ship the raw files.
* Every screen builds from `UIKit` (one cached Theme, cached StyleBoxFlats, the rewards atlas). Don't hand-roll button styles; add a Tone instead. Full-screen menus emit `SignalBus.ui_modal_changed` so the HUDs hide underneath (pause dropped from 195 to 116 draws).
* Stitch screens are layout references: they invent features (gems, races). Rebuild them in Godot with the game's real data; their hosted images (lh3.googleusercontent.com) can't be fetched here.
* Main menu (Nov 4 device feedback): the stage is the space right of the menu column. `_aim_camera` sets the camera distance from the free band's height and shifts the lens with `h_offset`/`v_offset`, so the auto never sits under the picker card at any aspect ratio; don't pin the auto with a fixed camera. New career lives in Settings, not beside Continue. `_refresh_status()` rebuilds every live number; call it after anything that changes money, level or the auto. `tests/shot_menu.tscn` renders the screens.
* `comfort_damping` multiplies jolts, so LOWER is smoother; show it through `MainMenu.comfort_score`. Condition and fuel belong to the auto (`GameState.parked_autos`): swapping keys repairs and refuels nothing, and a never-driven auto is fresh. The menu preview of another auto sets `show_damage = false` because `GameState.damage_state()` is the active auto's.
* The `lock` cell in the rewards atlas has "Lv" painted on it: use it only for level gates. Achievements use a grey medal until earned. Each achievement needs `ACH_<ID>` and `ACH_<ID>_DESC` in `translations/ui.csv` (phase 7 checks).
* The first-ride tutorial never auto-starts in test runs (persistence off); suites call `TutorialDirector.start()`. Anything that must stay calm during it reads `GameState.tutorial_active`; scripted riders/traffic come from `SignalBus.scripted_hail_requested` / `scripted_traffic_requested`.
* World markers (STOP line) sit at +0.1 m: road surfaces are at +0.045…+0.08, so anything lower is hidden under the road.
* Every shipped art/sound file lives under `assets/` (the app icon is `assets/icon/icon.png`); README screenshots go in `docs/images/`. Adding, replacing or removing an asset means updating `assets/README.md`, the folder's `CREDITS_*.md` and, for CC BY, `MainMenu.CREDITS`.

The canopy also samples an empty normal-map area, so it must skip `NORMAL_MAP` or a coloured canopy renders as shadow. The paint and glass shaders are ALWAYS on (stock yellow samples the texture's own colours) because they also draw the crash damage. Check every paint with `tests/shot_paint.tscn`.
* Visible crash damage (Nov 3): `tools/assets/bake_auto_parts.py` (+ `.mjs`) bakes `assets_src/models/player_auto_src.glb` into `assets/models/vehicles/player_auto.glb` with a part id per vertex in UV2.x (0 body, 1 left mirror, 2 right mirror, 3 windshield, 4 rear glass, 5 headlamp) and the body panels midpoint-subdivided so dents can bend (6.2k → 21.6k triangles, shape and UVs unchanged). Never split parts into separate meshes (a draw call each): `auto_paint.gdshader` pushes in up to 8 saved dents (`GameState.damage_marks`, mesh space in cm), discards a broken mirror by id and smashes the headlamp; `auto_glass.gdshader` cracks the windshield from the impact point (chip → spider web → shattered with holes). gltf-transform `prune()` strips UV2 as "unused" unless `keepAttributes: true`. Mirror debris bodies are pre-built and frozen (no instantiate while driving); physics bodies stay unscaled, the model scale goes on the mesh. After re-running `process_models.py` for the auto, run `bake_auto_parts.py --from-processed`.
* Damage smoke → fire is `scripts/vehicle/DamageFX.gd` on the player auto, from `GameState.damage_severity()` only: grey wisps from 35 % damage, black smoke from 80 %, flames from 88 %, a big fire when wrecked (condition 0: no engine power, `SignalBus.vehicle_wrecked`); the fire is three Kenney sprites (`flame_tongue`, `flame_body`, `fire_embers`) and the wreck fire is 1.7× bigger. `WindDustFX.gd` (child of the player auto only) rolls a low procedural dust haze across the road ahead during gusts (8 quads, `shaders/dust_haze.gdshader`: value noise, no texture, fades before the camera); no sprites, no wheel trail (Nov 4: the Kenney sprite dust read as cartoon), no dust while raining or wrecked. Emitter amounts change only between stages (changing `CPUParticles3D.amount` restarts it). The wreck panel (GarageUI) offers a rewarded `ad_wreck_repair` (full free repair; mock placeholder ad until real ads, 3/day), a paid roadside repair, or — with no money and no ad — a free patch-up to 15 % so the player is never stuck.
* The tutorial overlay must never dim or cover the road (Oct 31 playtest: lowering the dim was not the fix). Coach strip lives in the top HUD row gap, the speech bubble over the left kerb and folds after `SPEECH_S`; targets get a ring/arrow/chip only. Phase 11 asserts < 15 % coverage and no overlap with the road band. TouchHUD's status ribbon is muted while `GameState.tutorial_active`. Each tutorial step has a short `<line_key>_TASK` string.
* The player auto's driver is the owner's hero baked seated (`assets/models/hero/namma_auto_hero_seated.glb` by `tools/assets/bake_seated_hero.py`: posed rig → one mesh, one material, origin at the hip, `AutoRickshawModel.DRIVER_HIP`). He hides only in the cockpit camera. Release 1 has **no on-foot mode** (deferred to release 2, see README); don't re-add exit/enter buttons. Never put the animated 33-part hero GLB in the scene as-is (33 draw calls).
* Sketchfab "packs" often arrive as ONE merged mesh holding a showroom grid of many vehicles. Never point a traffic archetype or a city prop at the whole pack: split it into single vehicles (`tools/assets/process_vehicle_packs.py`), bake real size, then verify with `tests/shot_traffic.tscn` (side + rear renders). Real-size baked vehicles use `TrafficModelFit.attach(..., uniform = true)` so they are never squashed into another archetype's box.
* glTF multiplies the metallic/roughness texture by the material factors: any custom shader that reads a Tripo ORM texture must multiply by the source material's `metallic` / `roughness` (`auto_paint.gdshader` `metallic_scale`). The player auto's ORM is metallic = 1 everywhere with factor 0; reading `orm.b` alone turned a damaged or repainted auto into chrome that rendered black in shade (Nov 3). `tests/run_phase12_tests.gd` checks it.
* Steering wear does not pull the auto by default (`damage.tres` `steering_pull_deg = 0`): on the device a front-crash pull made the auto curve left on throttle alone, read as a control bug. If re-enabled it pulls only towards the more damaged side. Phase 12 drives a fully worn auto straight.
* AI-generated (Tripo) textures carry baked shading noise and metallic maps that render near-black on mobile; flatten them to a palette livery before simplifying (simplifying a photo atlas smears its UV seams).
* Physics ground is y = 0, but asphalt is drawn at `ROAD_Y` 0.06 and sidewalks at 0.08: vehicle visuals sit on the drawn road (`AutoRickshawModel.GROUND_Y`, `TrafficVehicleAI.ROAD_VISUAL_Y`), and people/props standing on kerbs take `SignalBus.surface_height(x, z, fallback)` (per-chunk 1 m raster of the drawn layers) — most kerbs have no sidewalk polygon, so a fixed height floats them.
* Anything that stands on the ground goes through `TrafficModelFit.stand_on_world()` or `SignalBus.ground_snap_requested.emit(node)` (snapped when its chunk's surface heights load). Never place a GLB's origin at ground height and assume its bottom is there: the traffic scooter is a 1 m box centred on its origin, several props start below 0. Parked vehicles scale uniformly to real length (`RoadsideParking.LENGTHS_M`). The parked two-wheeler is `two_wheeler_pack/scooter_parked.glb`.
* Two-wheeler riders are `PersonMesh.rider_node()` (baked real characters, origin at the hip, facing -Z); the procedural `seated_rider()` is only its fallback. Parked sport-bike files face +Z, so their riders turn round.
* People never stand inside buildings: `SignalBus.walkable(x, z)` reads a per-chunk 0.5 m mask of the building footprints (`WorldChunkStreamer._building_mask`, built on the worker thread). Walkers keep their kerb distance only where it is clear, else the widest strip between the road edge and the wall. Anything that places people at a kerb offset must check it.
* The chase camera recentres behind the auto by itself once you drive (`CameraRig._recenter`: 0.6 s after the last drag, above 1.2 m/s). Don't add a free-look that sticks while driving.
* Water (canals, ponds, temple tanks) comes from `data/world/water.json` (`tools/osm/build_water.py`, run after `build_world.py`; the OSM workflows run it): a ~4 m low-poly lattice with per-vertex bank distance (`shaders/water_lowpoly.gdshader`, flat-shaded facets, shallow→deep, foam), bank walls with gaps where roads CROSS water (bridges get parapets), water pulled back from roads that run ALONG a bank, ghat steps in temple tanks (the `steps` ring is the tank inset 5 m; `_ghat` grows it back out with MITRED offsets (`offset_ring`), so the top step meets the wall on every side — Nov 4: radial offsets from the tank centre left open water under Chitrakulam's west wall; steps top out at `GHAT_TOP_Y` under the 1.3 m `TANK_WALL_H` parapet; every tank footprint is in the walk mask (`_tank_blocks`), so walkers never enter one). Banks are tiled per 250 m and only drawn within 350 m. Never put a wall on every water edge again: it made an invisible wall across the Venkatesa Agraharam Road bridge. `tests/test_city_density.py` checks no bank sits on a carriageway; phase 9 drives across that bridge.
* The sky is `shaders/chennai_sky.gdshader`, built and driven by `Atmosphere.apply()` from the clock and the rain blend (coverage, zenith/horizon, cloud colours, stars). The Env takes ambient as a colour and no sky reflections, so the moving clouds never re-render a radiance cubemap; keep it that way (a sky using `TIME` that feeds reflections re-renders every frame). The old ProceduralSkyMaterial `sky_cover` at alpha 0.24 showed no clouds on the device.
* Android's `.mobile` defaults are HARD directional shadows and no MSAA, which looked jagged on the device; desktop renders never apply `.mobile` overrides. `GameState._apply_settings()` sets the shadow filter, shadow-atlas size and MSAA per graphics preset (`SHADOW_FILTER`, `SHADOW_ATLAS`, `MSAA_3D`). Check shadow changes on the Mobile renderer with `SHOT_DEVICE=1` / `SHOT_GFX` in `tests/shot_city.tscn`. Don't use SOFT_VERY_LOW: it dithers into grain.
* Traffic cars are one-mesh, vertex-coloured bakes (`assets/models/traffic/cars/`): Quaternius bodies by `tools/assets/bake_car_colours.py`, the owner's Mahindra Bolero (25 MB, 4k textures) by `tools/assets/bake_bolero.py` (seam-safe simplify, then texture -> per-triangle palette by majority vote; dirt counts as paint). A recolour is a new file, never a new texture. Never colour a stripe by triangle height on a low-poly body (zig-zags): lay thin strips just outside the flank. The police jeep's light bar is a separate surface whose material is named "Beacon"; `TrafficVehicleAI._light_beacon` gives it `shaders/police_beacon.gdshader`.
* Buses are the owner's Tripo e-bus repainted per livery by `tools/assets/bake_ebus.py` (`docs/BUSES.md`): cut the mesh at the zone heights BEFORE classifying (else zig-zag bands), lengthen by repeating the bay between the axles (never stretch: wheels go oval). Every bus slot carries all `BUS_VARIANTS` and picks one per respawn (`pick_bus_variant`); a slot that loaded one model for the session showed only two liveries ever.
* Real MTC stops: `data/world/bus_stops.json` (`tools/osm/build_bus_stops.py`, run after `build_world.py`; the OSM workflows run it). `BusStops` shows the nearest shelters through ONE MultiMesh and names only the nearest two (draw budget). A MultiMeshInstance3D at the world origin must not have a visibility range: it is measured from the node, so it culled every shelter. Buses treat the next stop as a stopped lead (`_bus_stop_gap`).
* Colour variety goes through `PaintSwap` + `shaders/paint_swap.gdshader` (per-instance HSV move of one source colour inside a UV rect; instance uniform, or MultiMesh custom data with `use_custom_data` set BEFORE the count). Add a model by listing its source colour / rect in `PaintSwap.CONFIG`, never by duplicating textures or models. Two-wheelers and NPC autos repaint per respawn (~30 % of autos electric blue/teal, some pink), pedestrians per spawn.
* People waiting at bus stops are static baked poses (`tools/assets/bake_waiting_people.py`, `assets/models/people/waiting/`); sarees never sit (the skirt follows the thighs). Only the two named stops get people (one draw call each, `BusStops.WAITING` slots, pre-instanced).
* Changing a `MultiMesh.instance_count` clears its transforms: set the count first, then write every transform.
* Roadside shops (`docs/STREET_SHOPS_AND_TRANSFORMERS.md`) come from `tools/assets/bake_street_shops.py`: one vertex-painted surface per livery + a painted sign quad (Baloo Thambi 2 via Raqm, generic shop words, never a real business name). Shop fronts face **-Z** (road side under `place_city_props` yaw); the old biryani GLB faced +X so its sign looked along the road. New liveries are a new `*_LIVERIES` entry, never a new texture. Placement (`add_street_shops`) reads dress poles/trees/transformers/parking, so run `build_street_dressing.py` → `build_roadside_parking.py` → `append_street_shops.py`. Every workflow that runs `build_street_dressing.py` must run the other two right after it (it rewrites every dress file; the Nov 2 `rebuild-chennai-density` run without them wiped all 21k parked vehicles on main). That workflow now fails before committing if trees, parking or shops come out empty. Shops: no shadows, ≤ 100 m view range, footprint in `_prop_blocks` (pedestrian walk mask).
* TNEB transformers are a double-pole structure in the EB pole line (`dress` `"xfmr"`: centre, yaw, outward unit vector); the structure replaces that pole and the tank sits `XFMR_OUT` behind the pole line, checked clear of every carriageway (a pole on one road's kerb can sit in a side road's mouth). `_transformer()` merges the owner's tank (`eb_transformer.glb`, read once in `_ready`; glTF colours are linear, the chunk mesh wants sRGB) into the chunk building mesh: no nodes, no draw calls.
* `editor/export/convert_text_resources_to_binary=false` must stay in `project.godot`. With Godot 4.5.1's default (true), every `Packed*Array` in a `.tres` loads empty in exported builds only: all quest dialogue `choices` vanished, `MissionRegistry` rejected the pack, and the Nov 5 device build showed no side quests while every source-tree suite passed. Passenger `home_zones` were silently empty too. Headless suites run from source, so they cannot see export-only data loss: to check it, `--export-pack` and run with `--main-pack`.
* Side quest content rules are in `docs/SIDE_QUESTS_PHASE6.md` (Nov 6 device test): every stop has a named place beside a building, words stay simple, the job is shown before Start, no hidden routes or unseen rules, cargo is safe until loaded, and a route never enters a closed zone. `tools/quests/validate_quests.py` and `tests/run_quest_experience_tests.gd` enforce them. The quest panel lives on the left kerb, under the GPS card: never put it across the road ahead or over the top-row buttons, and show an action button only when a tap will work.
* The sky (Nov 6 owner feedback: "bit grey"): `fog_sky_affect` must stay 0, because any fog on the sky turned the whole dome grey. All sky, cloud, sun and ambient colours come from `Atmosphere.SKY_KEYS` by minute (research in `docs/CHENNAI_SKY.md`). `sun_height` is negative through twilight, so colour continues after 18:30 while the light itself stops just above the horizon; the shader gets the true sun as `sun_dir`. Sunset red goes on the high cirrus, not the cumulus. Keep the shader at 7 noise samples or fewer. The moon is a lit sphere: its visible normal faces -moon_dir. `tests/shot_sky.tscn` renders the whole day.
* Quest places (`QuestPlaces` + `QuestPlaceKit`) stand in the city all the time: one shared one-surface mesh per kind, drawn within 120 m, no collision, and only the nearest 2 get a painted name. +Z faces the road and the kerb is often under 2 m, so nothing standing goes past z = 0.7. * City infill (Nov 6): `tools/osm/fill_empty_lots.py` runs last in the map rebuild. Don't connect `body_entered` with `CONNECT_ONE_SHOT` to catch a hit — the first body a fresh rigid body touches is usually the ground.
* Shop rows + hours (Nov 7): carts also stand in kerb rows of 5–6 (`build_beach_carts.py` ROWS) with a shop type and hours (`[…, open h, close h]`; open == close = shut all day; close may pass 24). ## 4. Closed-Loop Verification Protocol (Run After Every Task)
1. **Import & scene load check:**
   ```bash
   godot --headless --path . --import
   godot --headless --path . --quit-after 120   # must print no SCRIPT ERROR
   ```
2. **Phase test suite** (exit code 0 = pass):
   ```bash
   godot --headless --path . --fixed-fps 60 res://tests/run_crash_reporter_tests.tscn
   godot --headless --path . --fixed-fps 60 res://tests/run_phase1_tests.tscn
   godot --headless --path . --fixed-fps 60 res://tests/run_phase2_tests.tscn
   godot --headless --path . --fixed-fps 60 res://tests/run_phase3_tests.tscn
   godot --headless --path . --fixed-fps 60 res://tests/run_phase4_tests.tscn
   godot --headless --path . --fixed-fps 60 res://tests/run_phase5_tests.tscn
   godot --headless --path . --fixed-fps 60 res://tests/run_phase6_tests.tscn
   # … through run_phase11_tests — CI runs every suite; run them all before a PR
   ```
   After adding a new `class_name`, re-run `--import` first or the runner fails to parse. A parse error leaves the runner idling, so always wrap it in `timeout`.
   Do not use `-s` — autoload globals (`SignalBus`, `GameState`) don't resolve in `-s` scripts. Each new phase adds `tests/run_phaseN_tests.tscn` and a CI step.
3. **Perf probe** (exit 0 = within budget):
   ```bash
   xvfb-run -a godot --path . --rendering-method gl_compatibility --fixed-fps 60 res://tests/run_perf_probe.tscn
   ```
4. **CI:** the **Android Build** workflow (tests + APK export) must be green before a milestone is marked done.
5. **MCP interactive playtest** (when Godot MCP is connected): throttle 4 s → ≥ 35 km/h; full steer at 30 km/h → roll < 22°; horn → AI within 18 m shift sub-lane.
